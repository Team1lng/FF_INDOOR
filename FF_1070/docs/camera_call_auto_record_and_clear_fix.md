# 门口机来电切换清屏和自动记录修复

## 问题现象

1. 在 `door1` 监控界面收到 `door2` 呼叫并切换通道时，有概率出现一瞬间花屏或旧画面残留。
2. 门口机呼叫后，自动拍照/录像要等铃声播放结束后才开始，导致来电开始阶段没有记录。
3. 呼叫录像时间过短时也可能进入媒体列表。

## 原因分析

`door1` 到 `door2` 的来电切换是在 `camera` 页面内部完成，不会执行退出监控的清理逻辑。原流程只切换通道并重新打开监控，没有在页内切换前清理 GUI 层，因此旧画面或旧 UI 区域可能短暂残留。

自动拍照/录像原本放在铃声结束回调 `camera_call_ring_finish_cleanup()` 中触发，所以必须等铃声播放完才会开始记录。

底层录像保存判断使用毫秒时间戳，但原来的最小时长判断按 `3` 比较，实际只过滤了约 3ms 的异常短视频，没有达到 3 秒门槛。

## 修改内容

- 在门口机来电页内切换通道前，调用 `fb_gui_layer_rect_fill()` 清理 GUI 层，并刷新监控区域。
- 新增 `camera_call_auto_record_start()` 和短间隔重试任务，门口机来电后立即尝试自动拍照或录像；如果视频首帧还未稳定，则每 200ms 重试，最多重试约 3 秒。
- 铃声结束回调只负责关闭功放和音频通道，不再启动自动拍照/录像。
- 如果来电打断时已有录像或抓拍任务，先关闭旧任务，再按新通道重新启动自动记录，避免文件通道归属错误。
- 将呼叫录像最短保存时长修正为 `3000ms`，小于 3 秒或没有有效帧的临时录像不保存到媒体目录。

## 影响范围

- 影响 `layout_camera.c` 的门口机来电切换和自动记录触发时机。
- 影响 `video_record.c` 的短录像保存判断。
- 不改变手动录像、手动拍照的入口逻辑。

## 验证方式

```sh
cd FF_1070
make
```

板端验证：

1. 在 `door1` 监控界面触发 `door2` 呼叫，确认切换瞬间无明显旧 UI 残留或花屏。
2. 设置来电记录为拍照，触发门口机呼叫，确认呼叫开始后立即生成照片。
3. 设置来电记录为录像，触发门口机呼叫，确认呼叫开始后立即录像。
4. 呼叫录像不足 3 秒就结束，确认媒体列表不出现该短录像。
5. 呼叫录像大于等于 3 秒后结束，确认媒体列表能看到该录像。
